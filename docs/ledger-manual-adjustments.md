# 人工调账验证

本文档验证后台 `账务流水` 页面中的人工调账能力。

## 1. 功能说明

人工调账用于处理运营或财务确认后的余额修正，例如：

- 客服补偿
- 异常订单修正
- 测试环境余额修正

调账只影响用户 `可用余额`，不会修改冻结余额、充值记录或提现记录。

## 2. 页面入口

```text
账务流水 -> 人工调账
```

需要权限：

```text
ledger:adjust
```

默认只有 `admin` 角色拥有该权限。

## 3. 调账方向

- `增加用户可用余额`：用户可用账户 `CREDIT`，平台调账账户 `DEBIT`。
- `减少用户可用余额`：用户可用账户 `DEBIT`，平台调账账户 `CREDIT`。

每次调账都会生成 `MANUAL_ADJUSTMENT` 账务流水，并写入审计日志。

## 4. 验证增加余额

1. 进入某个用户详情页，记录某个 Token 的可用余额。
2. 进入 `账务流水`，点击 `人工调账`。
3. 输入用户 ID、Token，方向选择 `增加用户可用余额`。
4. 输入数量，例如 `0.1`。
5. 填写原因并提交。
6. 回到用户详情页刷新余额，预期可用余额增加。
7. 在 `账务流水` 中筛选 `MANUAL_ADJUSTMENT`，预期能看到该流水。
8. 点击 `查看` 分录，预期有两条分录。
9. 在 `审计日志` 中预期能看到 `人工调账`。

## 5. 验证减少余额

1. 进入 `账务流水 -> 人工调账`。
2. 方向选择 `减少用户可用余额`。
3. 输入小于用户可用余额的数量。
4. 提交后刷新用户详情，预期可用余额减少。

如果减少数量大于用户可用余额，后端会拒绝，错误码：

```text
INSUFFICIENT_BALANCE
```

## 6. 验证幂等键

1. 第一次调账时填写幂等键，例如：

```text
ticket-10001
```

2. 再次使用同一个幂等键提交。
3. 预期后端拒绝，错误码：

```text
DUPLICATE_ADJUSTMENT
```

## 7. 注意事项

人工调账是高风险操作，生产环境应配合：

- 更细权限
- 双人审批
- 工单号强制填写
- 调账额度限制
- 审计日志不可篡改
