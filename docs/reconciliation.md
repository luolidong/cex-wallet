# 账务对账页面验证

本文档验证后台 `账务对账` 页面。

## 1. 页面入口

启动 Java API 和前端后，进入后台左侧菜单：

```text
账务对账
```

页面每 10 秒自动刷新，也可以点击 `刷新`。

## 2. 当前对账口径

第一版按 Token 做账本一致性核对：

```text
账本总额 = 用户可用余额 + 用户冻结余额
期望账本 = 确认充值总额 - 已确认提现总额
差额 = 账本总额 - 期望账本
```

如果 `差额 = 0`，状态为：

```text
MATCHED
```

如果不为 0，状态为：

```text
MISMATCHED
```

## 3. 字段说明

- `用户可用`：用户可用账户余额汇总。
- `用户冻结`：用户冻结账户余额汇总。
- `账本总额`：可用 + 冻结。
- `确认充值`：已确认充值记录汇总。
- `确认提现`：已确认提现记录汇总，包含提现手续费。
- `待完成提现`：待审核、已批准、已广播提现汇总，已经冻结在账本里。
- `期望账本`：确认充值 - 确认提现。
- `热钱包地址`：从 `资产管理 -> 平台钱包` 读取 ACTIVE 的 HOT 钱包。
- `热钱包链上余额`：通过 EVM RPC 查询配置的热钱包地址余额。
- `资金覆盖差额`：热钱包链上余额 - 账本总额。
- `差额`：账本总额 - 期望账本。

mock 入账不纳入实际账本总额，也不纳入确认充值。

## 4. 验证步骤

1. 打开 `账务对账` 页面。
2. 正常情况下 ETH、USDT 应显示 `MATCHED`。
3. 做一笔充值并等待 scanner 入账。
4. 对应 Token 的 `确认充值` 和 `账本总额` 同时增加，状态仍为 `MATCHED`。
5. 申请一笔提现但不确认。
6. `用户可用` 减少，`用户冻结` 增加，`账本总额` 不变。
7. 提现确认后，`用户冻结` 减少，`确认提现` 增加，状态仍为 `MATCHED`。

## 5. 当前限制

- 第一版只核对本地账本和业务记录。
- 当前链上余额对账只支持 EVM native 和 ERC20。
- 当前只检查热钱包地址，后续可以增加充值地址归集前余额、异常快照和人工处理流程。

## 6. 热钱包地址配置

热钱包地址不再通过环境变量配置，改为在后台页面维护：

```text
资产管理 -> 平台钱包 -> 新增钱包
```

本地 Anvil 验证建议新增一条：

- 链：`Ethereum`
- Token：不选，表示链级钱包
- 钱包角色：`HOT / 热钱包`
- 状态：`ACTIVE`
- 地址：`0xf39fd6e51aad88f6f4ce6ab8827279cfffb92266`

如果某个 Token 配置了 Token 级 HOT 钱包，对账会优先使用 Token 级地址；否则使用同一条链上的链级 HOT 钱包。
